# 版本记录：v1.3-task-workbench-bulk-audit

## 1. 本轮目标

本轮目标是在 V1.2 已完成客户分配、查询型销售待办、客户详情策略增强、资料包绑定、租户审计日志查询和销售概览的基础上，把系统推进到“任务驱动型业务工作台”。

本轮属于功能补充和可维护性提升：新增真实任务模型，支持销售处理任务、企业管理员批量操作客户、运营管理任务，并补齐平台级审计日志视图。

本轮仍明确不做企业微信 API 真实接入、不做智能客服、不做复杂 AI、不做财务、人事、行政、审批、OA，也不做大规模 UI 重构。

## 2. 背景与上下文

本轮承接 `custom/notes/v1.2-sales-todo-strategy-materials.md`。V1.2 的待办仍主要基于 Lead 查询规则，例如 `nextFollowAt`、`intentionLevel`、`stage` 等字段动态计算。这个方案轻量、直观，但不适合作为后续消息提醒、延期、取消、完成、SLA 或企业微信应用消息的长期基础。

V1.3 的核心变化是新增 `FollowTask`，让“今天该做什么”从临时查询变成可被记录、处理和审计的业务对象。

## 3. 问题分析

V1.2 的问题不是权限或数据隔离，而是任务没有实体：销售不能标记完成，管理员不能统计任务完成情况，延期和取消无法沉淀，批量操作也不能自然生成后续跟进任务。

真正的核心矛盾是：系统已经知道客户状态，但还缺少“销售动作”的持久化容器。没有任务模型，就无法稳定支持提醒、复盘、协作和审计。

本轮还补充了客户列表批量操作，因为客户分配和阶段推进在真实运营中经常不是单条发生。批量操作必须服务端校验 `tenantId`，并写入 AuditLog，避免成为新的越权入口。

## 4. 候选方案比较

### 方案 A：新增 FollowTask 模型，但保留现有 Lead 阶段

核心思路是新增任务表承接待办和跟进动作，同时不新增 LeadStage。现有 `NEW`、`QUOTED`、`TO_REACTIVATE` 等阶段足以支撑 V1.3 的生命周期表达。

优点：改动集中，兼容 V1.0-V1.2 的列表、看板、导出和测试；任务模型可以独立演进。

缺点：客户生命周期语义仍依赖已有 stage，暂时没有 `ASSIGNED`、`REACTIVATED` 等更细状态。

最终选择该方案，因为本轮重点是任务驱动而不是重写生命周期。

### 方案 B：同时新增 FollowTask 和更多 LeadStage

核心思路是把客户生命周期和任务系统一起细化。

优点：语义更完整，可以表达已分配、已激活、老客户等状态。

缺点：会牵动 seed、列表筛选、看板统计、导出、旧测试和阶段更新逻辑，改动面过大。

最终放弃该方案，避免 V1.3 膨胀为大范围生命周期重构。

## 5. 最终决策

本轮采用 `FollowTask` 独立模型：

- 任务有 `type`、`status`、`priority`、`dueAt`、`completedAt`、`cancelledAt`。
- 任务可关联 Lead、owner 和 createdBy。
- 销售只看 `ownerId` 等于自己的任务。
- 企业管理员和运营看本租户全部任务。
- 任务创建、完成、延期、取消全部写入 AuditLog。
- 批量操作继续走 Server Actions，避免新增 API 层和重复权限面。

## 7. 本轮优点

任务从“查询结果”变成“业务对象”，可以完成、延期、取消并被审计。销售工作台的行为更接近真实业务场景。

批量操作让企业管理员和运营能按真实工作流处理多条线索，同时仍在 Server Action 中校验 tenant 和角色。

平台级审计日志补齐平台方排查能力，可以跨租户查看关键操作，但仍遮蔽 metadata 中的敏感词。

## 8. 本轮缺点与代价

当前任务自动生成规则仍偏基础：会在公开表单、分配、阶段变化、下次跟进时生成任务，但还没有做去重、SLA、任务模板配置或定时扫描。

任务模型没有单独的手动创建页面；本轮主要通过关键动作自动生成任务。后续如要运营创建任务，需要新增手动任务入口。

批量操作是服务端表单式体验，没有全选、分页批量、进度反馈和撤销能力。

平台审计日志只做查询，不做导出和风险分级。

## 10. 本轮结论

V1.3 的关键结论是：任务模型是后续提醒、企业微信应用消息、销售 SLA、团队复盘的必要基础。当前实现已经把销售工作台从查询型待办推进到任务驱动闭环。

## 11. 下一轮建议

1. 增加手动创建任务和任务模板配置，让运营能主动安排销售动作。
2. 增加任务去重和 SLA 规则，避免同一客户因多次操作生成过多任务。
3. 在接入企业微信 API 前，先把任务提醒队列和消息发送边界设计清楚。
