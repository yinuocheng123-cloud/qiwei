# 版本记录：v1.4.2-sales-demo-package

## 1. 本轮目标

本轮目标不是继续开发业务功能，也不是扩数据库、接企业微信 API 或引入复杂 AI，而是在 V1.4.1 演示说明页已经完成的基础上，补一套对外演示、销售讲解和合作沟通所需的文字材料包。

优先级高的原因是：系统虽然已经有整木行业样板数据和演示说明页，但如果没有统一的讲解脚本、FAQ、合作边界和销售沟通流程，实际对外演示时仍然容易出现“每个人讲法不一样、老板听不懂、销售只会讲功能”的问题。

本轮属于可交付材料补充、销售支持和演示闭环完善。

## 2. 实际完成内容

1. 新建 `custom/sales/` 目录，用于集中存放对外演示与销售材料。
2. 新增 5 分钟演示脚本，围绕 dashboard、客户列表、四类客户详情、销售工作台和演示说明页整理可直接照读的讲解顺序。
3. 新增老板版讲解话术，把系统定位翻译成传统企业老板更容易理解的表达。
4. 新增常见问题回答，覆盖 CRM、企业微信、SCRM、数据归属、合作边界、费用、行业复制和 AI 等高频问题。
5. 新增一页纸合作说明，用于快速对外说明产品、问题、价值、周期、费用和权属边界。
6. 新增销售沟通流程，帮助销售从首次沟通推进到演示、诊断、合作建议和成交推进。
7. 更新 `AGENTS.md` 最新一期路径到本记录。

## 4. 每份文件用途

### `v1.4.2-demo-script.md`

用于 5 分钟内完成系统价值演示，适合销售、创始人或交付人员在打开 `zhengmu-demo` 时按步骤讲解。

### `v1.4.2-boss-talk-script.md`

用于面向传统企业老板沟通，把技术概念翻译成“客户有没有被接住、老板能不能看清”的语言。

### `v1.4.2-faq.md`

用于统一高频问答口径，避免不同销售在 CRM、企业微信、数据归属、合作边界和后续扩展上说法不一致。

### `v1.4.2-one-page-proposal.md`

用于快速发给潜在客户，帮助对方在一页内理解产品是什么、解决什么问题、怎么收费以及合作边界是什么。

### `v1.4.2-sales-flow.md`

用于销售团队内部使用，帮助把首次沟通、客户判断、系统演示、诊断结论、合作建议和成交推进串成标准流程。

## 5. 是否修改系统代码

本轮原则上不改系统页面。

实际也没有修改业务代码、页面、数据库 schema、测试逻辑或权限体系，只新增销售材料文档和正式记录，并更新了 `AGENTS.md` 的最新一期路径。

## 6. 验证结果

本轮要求执行的基础验证命令如下，且已全部通过：

1. `npm.cmd run prisma:generate`
2. `npx.cmd tsc --noEmit`
3. `npm.cmd run lint`
4. `npm.cmd run build`

补充说明：

1. 本轮只新增文档文件与 `AGENTS.md` 路径更新，没有修改业务逻辑；
2. `next build` 仍正常产出 `/app/[tenantSlug]/demo-guide` 等既有动态路由；
3. 本轮没有新增 Playwright 用例，也没有重跑数据库脚本，因为需求范围仅为销售材料输出。

## 7. 风险与未完成项

1. 当前销售材料仍然以整木行业样板为中心，适合当前 `zhengmu-demo` 对外演示，但还没有针对床垫、大理石、CNAS 等行业做独立版本。
2. 本轮输出的是文字材料，不包含 PPT、海报、报价单模板或对外 PDF 版式。
3. FAQ 已覆盖常见问题，但真实销售过程中仍可能因为客户规模、行业成熟度、是否已有 CRM/企微系统而需要二次改写。

## 8. 下一步建议

1. 如果后续继续做 V1.4.x 的销售支持，可以把这套文字材料进一步整理成 PPT 目录、报价清单和标准对外 PDF。
2. 可以按行业复制当前材料包框架，后续分别产出床垫、大理石、CNAS 等样板销售包。
3. 如果后续销售反馈某些问题反复出现，可以继续扩展 FAQ，并把成交话术与失败原因沉淀到 `custom/sales/` 下。
