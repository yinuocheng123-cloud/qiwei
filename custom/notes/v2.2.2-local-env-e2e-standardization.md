# 版本记录：v2.2.2-local-env-e2e-standardization

## 1. 本轮目标

本轮目标不是新增业务功能，也不是调整销售路径，而是标准化本地开发和 E2E 测试环境，让 V2.2 / V2.2.1 smoke 测试可以稳定依赖 PostgreSQL、Prisma、Seed 和 Playwright 流程运行。

本轮不接真实企业微信，不接真实 AI，不做自动客户回复，不 push、不部署、不提交。

## 2. 背景与上下文

V2.2 和 V2.2.1 的 `typecheck`、`lint`、`build` 已经通过，但 Playwright E2E 在登录阶段失败。失败信息是：

```text
Can't reach database server at 127.0.0.1:55432
```

这说明失败原因是本地 PostgreSQL 没有启动，或 `127.0.0.1:55432` 没有可用数据库服务，不是业务代码问题。

## 3. 问题分析

当前 `.env` 指向：

```text
postgresql://postgres@127.0.0.1:55432/wecom_growth_hub_demo?schema=public
```

因此本地测试需要 PostgreSQL 监听宿主机 `55432` 端口。当前机器 PowerShell 中 `docker --version` 和 `docker compose version` 都不可用，说明不能假设 Docker 已安装。

项目已有 `prisma/seed.ts`，并且会生成 smoke 测试需要的账号和演示数据，例如：

- `boss@zhengmu.local / 123456`
- `sales@zhengmu.local / 123456`

所以本轮不新增业务 seed，只复用现有 seed。

## 4. 候选方案比较

方案一：要求每次手动启动 PostgreSQL。

优点是改动最少。缺点是新环境容易忘记端口、数据库名和初始化顺序，Playwright 失败时也容易误判为业务问题。本轮不采用单一手动方案。

方案二：新增 Docker Compose 管理 PostgreSQL。

优点是环境更可复制，数据库端口和 `.env` 可以固定对齐。缺点是当前机器还未安装 Docker Desktop，需要文档说明。本轮采用。

方案三：新增一键 PowerShell 检查脚本。

优点是能把 Node、npm、Docker、PostgreSQL、Prisma、Seed、typecheck、lint、build、smoke 测试串起来，并在 Docker 不可用时给出清晰提示。本轮采用。

## 5. 最终决策

本轮采用：

- 新增 `docker-compose.yml`，只启动 PostgreSQL。
- 新增 `scripts/dev-check.ps1`，标准化本地验证流程。
- 新增 `scripts/db-reset-local.ps1`，为 `db:reset` 加本地数据库安全保护。
- 新增 `custom/dev/local-env-setup.md`，说明 Docker 不可用时如何处理。
- 更新 `package.json`，补齐数据库和 smoke 测试脚本。
- 更新 README，补充本地开发环境与 E2E 测试章节。

## 6. 具体实现

新增 `docker-compose.yml`：

- 服务名：`postgres`
- 镜像：`postgres:16`
- 宿主机端口：`55432`
- 容器端口：`5432`
- 数据库：`wecom_growth_hub_demo`
- 用户：`postgres`
- 使用命名卷 `qiwei-postgres-data`
- 使用 `POSTGRES_HOST_AUTH_METHOD=trust` 对齐当前 `.env` 无密码连接串

新增 package scripts：

- `db:generate`
- `db:push`
- `db:seed`
- `db:reset`
- `test:e2e:v22`
- `test:e2e:v221`

`db:reset` 不直接写成裸 `prisma migrate reset`，而是调用 `scripts/db-reset-local.ps1`，先检查 `DATABASE_URL` 必须指向 `127.0.0.1:55432/wecom_growth_hub_demo`，避免误删非本地库。

## 7. 本轮优点

本地环境路径更清楚：从 `Set-Location D:\ceshi\qiwei` 开始，避免 PowerShell 中误用 `cd /d`。

数据库端口更清楚：`55432` 是宿主机 PostgreSQL 端口，Docker 容器内仍是 `5432`。

E2E 失败归因更清楚：登录阶段连不上数据库时，不再误判为业务代码问题。

## 8. 本轮缺点与代价

当前机器 Docker 仍不可用，因此本轮无法实际用 Docker 拉起 PostgreSQL，也无法在当前环境完成 V2.2 / V2.2.1 Playwright smoke。

`docker-compose.yml` 使用 trust 认证，是为了对齐当前 `.env` 的无密码本地连接串，只适合本地开发，不适合生产。

## 10. 本轮结论

V2.2 / V2.2.1 smoke 测试失败的直接原因是本地数据库不可用。标准化后的本地流程应先启动 PostgreSQL，再执行 Prisma generate、db push、seed，最后运行 Playwright。

## 11. 下一轮建议

1. 安装 Docker Desktop，重新打开 PowerShell 后确认 `docker --version` 和 `docker compose version`。
2. 执行 `docker compose up -d`，确认 `127.0.0.1:55432` 可连接。
3. 执行 `scripts/dev-check.ps1`，一次性跑完数据库初始化和 V2.2 / V2.2.1 smoke。
