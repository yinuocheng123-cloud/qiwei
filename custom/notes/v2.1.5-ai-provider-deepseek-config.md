# 版本记录：v2.1.5-ai-provider-deepseek-config

## 1. 本轮目标

本轮目标是在不改 Market Claw 主链路的前提下，新增租户级 AI Provider 基础配置与安全调用框架。它属于基础设施补充，不是资料投喂、客户回复、销售训练或候选知识审核的业务逻辑改造。

核心目标是让系统先具备配置、测试、调用日志、失败降级和权限边界，后续再决定哪些场景可以安全地接入 AI 增强。

## 2. 为什么先接 AI Provider 配置

此前 Market Claw 主要依赖规则版能力。如果直接把 AI 接进资料投喂或客户回复主链路，会同时引入 API Key 安全、调用失败、成本、日志、权限、风险等级和人工审核边界等问题。

所以本轮先做 Provider 配置和最小调用框架，把“能不能安全调用、失败怎么记录、页面怎么降级、谁能配置”先跑通，再进入业务增强。

## 3. 为什么优先支持 DeepSeek

DeepSeek API 支持 OpenAI-compatible 的 Chat Completions 格式，适合先用统一调用服务承接。这样既能优先支持 DeepSeek，也能保留其他 OpenAI-compatible 服务的接入空间。

本轮不写死模型列表，只提供默认模型占位和后台可配置字段。模型名称应以后续官方文档或企业实际可用模型为准。

## 4. DeepSeek 配置说明

默认 Provider 为 `DEEPSEEK`，默认 baseUrl 为 `https://api.deepseek.com`，Chat Completions 请求由服务层统一拼接 `/chat/completions`。页面支持配置 model、apiKey、temperature、maxTokens 和启用状态。

API Key 不完整回显，留空保存时保留旧值，勾选清空时才清除已保存 Key。当前 `apiKeyEncrypted` 仍是项目内占位字段，生产环境需要接入正式密钥加密或安全存储方案。

## 5. OpenAI-compatible 扩展说明

本轮新增 `OPENAI_COMPATIBLE` Provider，用于后续接入兼容 Chat Completions 的服务。调用服务不把 DeepSeek 逻辑写死在业务页面，而是通过 baseUrl、model 和 provider 统一构造请求。

同时保留 `MOCK` Provider，用于无真实 API Key 时做页面测试、演示和回归验证。

## 6. 配置页面说明

新增页面 `/app/[tenantSlug]/ai-settings`，名称为“AI 能力配置”。页面包含当前配置状态、Provider 选择、baseUrl、model、apiKey、temperature、maxTokens、启用状态、保存配置、清空配置、测试连接、最近测试结果、最近调用日志和安全边界说明。

页面明确提示：AI 输出只是建议，候选知识仍需人工审核，客户回复仍由销售确认，风险等级仍以系统规则和人工确认优先。

## 7. 调用服务说明

新增 `src/lib/ai-provider.ts`，包含：

- `getTenantAiProviderConfig`
- `testAiProviderConnection`
- `callAiTextCompletion`
- `callAiJsonCompletion`
- `maskApiKey`
- `recordAiCallLog`

服务层统一处理配置读取、Chat Completions 请求、Mock 测试、安全失败和日志记录。调用失败不会抛穿业务页面。

## 8. 调用日志说明

新增 `AiCallLog`，记录 provider、model、purpose、status、errorMessage、token 用量、latencyMs、createdById 和 createdAt。

日志不记录完整 prompt，不记录完整 AI 输出，不记录完整 API Key。服务层会记录 prompt hash，便于排查同类请求，但不暴露原文。

## 9. 安全降级说明

未配置、未启用时记录 `SKIPPED`；启用但缺少 API Key 或真实请求失败时记录 `FAILED`；Mock 测试可记录 `SUCCESS`。

没有 AI 配置时，系统继续使用规则版能力。本轮没有把 AI 接入 Market Claw 主链路，因此调用失败不会影响资料投喂、客户详情页回复、销售训练或候选知识审核。

## 10. 权限说明

TENANT_ADMIN 可查看、保存、清空、测试配置并查看调用日志。OPERATOR 可查看配置状态、执行测试连接并查看调用日志，但不可查看完整 API Key，也不可清空高权限配置。SALES 不显示 AI 配置入口，直接访问会被拒绝。PLATFORM_ADMIN 不扩大租户侧业务权限。

## 11. AuditLog 说明

本轮补充以下审计动作：

- `ai_provider_config_created`
- `ai_provider_config_updated`
- `ai_provider_config_cleared`
- `ai_provider_config_tested`
- `ai_provider_call_succeeded`
- `ai_provider_call_failed`
- `ai_provider_call_skipped`

metadata 只记录 tenantId、provider、model、purpose、status、latencyMs、createdById、promptHash 和错误摘要，不记录完整 API Key、完整 prompt 或完整 AI 输出。

## 12. 明确本轮不让 AI 直接写业务数据

本轮 AI 调用服务只返回结构化结果并写调用日志，不自动创建知识、不自动采纳候选、不自动降低风险等级、不自动创建任务、不自动触达客户。

## 13. 明确本轮不改 Market Claw 主链路

本轮没有直接改资料投喂拆解、客户详情页回复生成、销售训练生成和候选知识审核主链路。后续如果接入 AI 增强，应先从沙盒或预览场景开始，再逐步进入人工审核流程。

## 15. 风险与未完成项

当前 API Key 字段仍是占位保存，不是正式加密存储。生产环境必须接入正式密钥管理方案。

当前没有重试队列、成本统计、限流控制和模型健康检查。当前 JSON 调用只做基础容错，不保证模型一定返回稳定结构。

## 16. 下一步建议

2. 再考虑资料投喂候选知识“预览增强”，但必须保持人工审核。
3. 之后再评估 Agent Library 的最小调用规范、成本统计和调用权限分层。
