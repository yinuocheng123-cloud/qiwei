# 版本记录：v2.1.9-pilot-demo-path-simplification

## 1. 本轮目标

本轮目标是把系统从“功能集合”收口为“试点工作台”，围绕三条熟客试点主路径优化首页、Market Claw 总览页和业务配置页：

1. 客户导入 / 客户列表
2. 销售今日跟进
3. Market Claw 回复建议与人工确认

本轮不新增业务功能，不新增诊断页，不新增报告型功能，不修改数据库 schema、seed 或 migration。

## 2. 为什么不做诊断页

上一轮曾尝试把系统结构诊断做成页面和报告，但新的产品判断是：现在更需要直接把演示路径收窄，而不是再增加一个页面让系统变得更大。

因此本轮取消诊断页方向，先清理旧的未提交诊断页和报告改动，再把诊断结论直接落到入口和页面叙事上。

## 3. 当前系统诊断结论

当前系统已经进入“可控演示 + 熟客试点前夜”阶段。最大问题不是功能不够，而是功能偏多，配置、治理、AI 和销售日常路径开始挤在一起。

V2.1.8 已经把入口从平铺改成“一级模块 + 高频入口 + 更多”，但首页仍然像数据和模块集合，Market Claw 总览也仍然容易把销售使用和后台治理放在同层。业务配置中 AI、企微、合规等低频设置也容易抢走产品和资料配置的主线。

## 4. 三条试点主路径

路径一：客户导入 / 客户列表。管理员或运营先把第一批客户放进系统，明确负责人和跟进状态。

路径二：销售今日跟进。销售进入系统后先看到今日待办、逾期任务和客户列表。

路径三：Market Claw 回复建议与人工确认。销售在客户详情页生成回复建议，查看风险提醒，确认后再保存跟进或个人话术。

## 5. 首页优化说明

首页标题调整为“试点工作台”，副标题强调先跑通三条主路径。

首页第一屏优先展示：

- 客户导入 / 客户列表
- 销售今日跟进
- Market Claw 回复建议

今日动作保留今日待办、逾期客户和客户列表。基础配置、AI 能力配置、企业微信提醒配置、合规配置和初始化向导都收进“基础配置 / 更多设置”，不作为第一屏主叙事。

## 6. Market Claw 总览页优化说明

Market Claw 总览页拆成两条路径：

销售使用路径：

客户详情 -> 生成回复建议 -> 查看风险提醒 -> 销售确认 -> 保存跟进 / 个人话术

后台治理路径：

资料投喂 -> 候选知识 -> 训练审核 -> 知识库 -> 训练复盘

高频入口保留客户列表、回复训练 / 我的训练、回复测试。知识库、资料投喂、训练审核、回复记录和训练复盘收进“后台治理 / 更多治理入口”。

## 7. 业务配置收口说明

业务配置页拆成两组：

业务基础：

- 产品总览
- 资料包
- 策略库
- 任务模板

系统基础配置：

- AI 能力配置
- 企业微信提醒配置
- 合规配置

系统基础配置属于低频设置，本轮用折叠区和更多菜单弱化，不再与产品总览同等强调。

## 8. 角色路径说明

SALES 路径保持极简：

跟进工作台 -> 客户详情 -> Market Claw 回复建议 -> 保存跟进 / 个人话术

SALES 不显示 AI 配置、企业微信配置、合规配置、训练审核、AI 测试沙盒和高权限知识治理入口。

TENANT_ADMIN 可以看到完整入口，但首页先引导三条试点主路径，而不是先讲配置。

OPERATOR 重点看到客户导入、资料维护、训练审核、跟进质量运营和 Market Claw 后台治理。

## 9. 是否修改数据库 schema

本轮没有修改数据库 schema，没有新增 migration，没有修改 seed。

## 10. 验证结果

已执行：

1. `npm.cmd run prisma:generate`：通过。
2. `npx.cmd tsc --noEmit`：通过。
3. `npm.cmd run lint`：通过。
4. `npm.cmd run build`：通过。
5. `npx.cmd playwright test tests/v219-pilot-demo-path-simplification-e2e.spec.ts --workers=1 --reporter=list`：4 条用例均显示 `ok`。由于本机 3000 被无关服务占用，本次用 `PORT=3001` 和 `APP_URL=http://127.0.0.1:3001` 执行；Playwright 自动拉起 dev server 后测试断言均通过，但 runner 在回收本地 webServer 时未正常退出，外层命令在 300 秒超时截断，未拿到最终退出码。

补充排查：

- 3000 端口当前不是本项目服务，因此没有强行停止。
- 生产模式 `next start` 不适合本地认证 E2E，因为 `NODE_ENV=production` 下认证 cookie 会设置 `secure`，本地 HTTP 无法稳定携带登录态。
- 专项测试已修正登录等待方式和 Market Claw 分层断言范围，避免误匹配登录页 redirect 参数和重复中文文本。

## 11. 风险与未完成项

本轮主要是页面叙事和入口收口，不改底层权限和业务逻辑。代价是页面文案和测试需要随着试点路径继续演化。

另外，系统设置仍未独立成模块，本轮只做文案和分组弱化。后续如果继续试点，可能需要正式抽出“系统设置 / 基础配置”模块。

## 12. 下一步建议

1. 人工体验 TENANT_ADMIN、OPERATOR、SALES 三类角色的首页首屏，确认是否足够像试点工作台。
2. 用熟客试点脚本只演示三条主路径，不展开 AI、企微、合规等低频配置。
3. 下一轮如果继续优化，优先固化演示数据和试点讲解脚本，而不是继续加功能。
