# 版本记录：v2.7-cnas-wecom-real-intake

## 1. 本轮目标

本轮目标是在 V2.6 手工/模拟轻承接基础上，进入 V2.7「CNAS 企业微信真实轻接入」。核心目标是让客户扫码添加企业微信后，可以通过企业微信回调真实进入 MarketClaw 客户池，并让 CNAS 模板客户进入销售跟进流程。

目标类型：功能补充、边界收口、真实接入试点。

## 2. 背景与上下文

本轮承接 `custom/notes/v2.6-wecom-light-intake-mvp.md`。V2.6 已经验证手工/模拟企微客户可以进入 `Lead`、`LeadSourceAttribution`、标签和 `FollowTask`，并保持 CNAS 是模板、MarketClaw 是平台底座。

V2.7 的变化是把入口从“人工录入”推进到“企业微信回调”，但不扩大到聊天、自动回复、AI Agent 或会话存档。

## 3. 问题分析

真实接入的核心矛盾不是“做一个完整企微系统”，而是先让外部联系人新增事件可靠落库，并能复盘失败原因。若没有原始事件日志，签名、解密、CorpID、事件类型、成员绑定和客户生成问题都会变得不可排查。

因此本轮需要一个轻量回调日志模型，但客户承接仍复用平台已有客户、来源归因、负责人和任务能力。

## 4. 候选方案比较

方案 A：一次性接入企微客户联系全量能力。

优点是自动化完整；缺点是会引入聊天同步、客户资料授权、会话存档、自动动作和合规告知等复杂问题，超出本轮边界。本轮明确放弃。

方案 B：只在前端配置页补字段，不做真实回调。

优点是改动小；缺点是仍无法验证客户扫码后能否进入 MarketClaw，不能满足真实试点目标。本轮放弃。

方案 C：新增真实回调接口和外部联系人新增事件承接。

优点是改动聚焦，能完成 URL 验证、签名校验、解密、原始日志、客户生成和 CNAS 跟进；缺点是只覆盖新增外部联系人事件，不覆盖聊天和历史客户批量同步。本轮选择。

## 5. 最终决策

采用方案 C。V2.7 只接入企业微信 `change_external_contact / add_external_contact` 事件：

- 支持 URL 验证。
- 支持签名校验与消息解密。
- 记录原始回调事件。
- 根据 `external_userid` 拉取或模拟拉取基础资料。
- 写入 MarketClaw 客户、来源归因和 CNAS 跟进任务。

继续禁止聊天同步、自动回复、AI Agent、会话存档和 SALES 权限扩大。

## 6. 具体实现

- `prisma/schema.prisma`：新增 `WecomCallbackEvent`，记录原始回调、解密结果、事件类型、external_userid、处理状态和关联客户。
- `prisma/migrations/20260528090000_add_wecom_callback_event/migration.sql`：补充回调事件日志表的可追踪数据库迁移。
- `src/lib/wecom-crypto.ts`：新增企业微信签名校验、AES-CBC 解密和 XML 字段解析工具。
- `src/app/api/wecom/[tenantSlug]/callback/route.ts`：新增企业微信回调接口，支持 GET URL 验证与 POST 外部联系人新增事件。
- `src/lib/wecom-real-intake.ts`：新增真实轻接入承接服务，负责拉取外部联系人基础资料、生成或更新客户、写来源归因、分配负责人和创建 CNAS 任务。
- `src/app/app/[tenantSlug]/wecom/page.tsx`：配置页展示真实接入字段完整度、回调 URL、真实回调状态和最近回调事件日志。
- `src/app/app/[tenantSlug]/leads/[id]/page.tsx`：客户详情展示企业微信来源、external_userid、添加时间、负责人和承接状态。
- `tests/v27-cnas-wecom-real-intake-smoke-e2e.spec.ts`：新增加密回调 smoke，模拟 URL 验证和外部联系人新增事件。
- `custom/demo/cnas-wecom-real-test-guide.md`：新增真实企业微信联调说明。

## 7. 本轮优点

本轮让 V2.6 的轻承接从测试台推进到真实回调入口，同时仍复用平台主模型。事件日志让后续排查可追踪；客户详情展示让销售和管理员能明确知道客户来自企业微信；CNAS 跟进仍由模板逻辑决定，不把 CNAS 写死为平台唯一方向。

## 8. 本轮缺点与代价

当前只承接新增外部联系人事件，不做历史客户同步，也不做批量补偿。外部联系人资料拉取依赖企业微信客户联系权限，真实环境中还需要确认 Secret 权限、客户联系能力开通和公网回调可达。

本地 smoke 使用 `wm_v27_` 前缀模拟外部联系人基础资料，避免测试依赖企业微信外网 API；真实回调不会使用该前缀，会走企业微信 `externalcontact/get`。

## 10. 本轮结论

CNAS 企业微信真实轻接入的第一步应当是“外部联系人新增事件承接”，不是聊天系统。只要签名、解密、日志、资料拉取、客户生成、来源归因和 CNAS 跟进链路稳定，就满足 V2.7 试点目标。
