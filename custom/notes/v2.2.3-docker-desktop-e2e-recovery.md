# 版本记录：v2.2.3-docker-desktop-e2e-recovery

## 1. 本轮目标

本轮目标是继续处理本地开发 / 测试环境，让 PostgreSQL、Prisma、Seed、Playwright smoke 流程尽可能跑通。本轮不是产品开发，不新增业务功能，不改销售路径，不接真实企业微信或真实 AI。

## 2. 背景与上下文

V2.2.2 已经补齐 Docker Compose、PowerShell 检查脚本、README 和本地环境文档，但上一轮因为 Docker 不可用，未能跑通 E2E。

本轮继续从 `D:\ceshi\qiwei` 处理本地环境。

## 3. 问题分析

环境诊断结果：

- `docker --version` 已可用。
- `docker compose version` 已可用。
- `docker info` 失败，返回 `Docker Desktop is unable to start`。
- `com.docker.service` 处于 stopped，当前 PowerShell 无法启动该服务。
- `wsl --status` / `wsl -l -v` 输出异常，疑似 WSL2 或 Docker Desktop Engine 需要系统层修复。
- `127.0.0.1:55432` 初始不可连接。

因此 Docker CLI 可用并不等于 Docker Engine 可用。本轮没有继续强压 Docker，而是走本机 PostgreSQL fallback。

## 4. 候选方案比较

方案一：继续尝试 Docker Desktop。

已经尝试启动 Docker Desktop 并轮询 `docker info`，但 Engine 始终不可用。继续反复尝试收益不高，且可能需要管理员权限、WSL2 更新、Docker Desktop 登录或重启电脑。

方案二：使用本机 PostgreSQL fallback。

本机存在 `D:\tools\pgsql17\pgsql\bin\postgres.exe`、`pg_ctl.exe`、`psql.exe`，项目也已有 `custom/experiments/postgres-data` 数据目录。该方案可以不依赖 Docker，直接满足 Prisma 和 Playwright 对 `127.0.0.1:55432` 的要求。本轮采用。

## 5. 最终决策

本轮使用本机 PostgreSQL 17 启动 `127.0.0.1:55432`，创建或复用 `wecom_growth_hub_demo`，然后执行 Prisma、Seed、typecheck、lint、build 和 V2.2 / V2.2.1 smoke。

同时更新 `scripts/dev-check.ps1`：当 Docker 不可用或数据库不可连接时，尝试使用本机 PostgreSQL fallback，而不是直接把 E2E 标记为代码失败。

## 6. 具体实现

执行的关键恢复命令：

```powershell
D:\tools\pgsql17\pgsql\bin\pg_ctl.exe -D D:\ceshi\qiwei\custom\experiments\postgres-data -l D:\ceshi\qiwei\custom\experiments\postgres-v222.log -o "-p 55432" start
```

数据库恢复后：

- `pg_isready` 返回 `accepting connections`。
- 端口 `55432` 由本机 PostgreSQL 监听。
- `wecom_growth_hub_demo` 已存在。

更新文档：

- `custom/dev/local-env-setup.md`
- `custom/notes/v2.2.2-local-env-e2e-standardization.md`
- `README.md`
- `AGENTS.md`

新增记录：

- `custom/notes/v2.2.3-docker-desktop-e2e-recovery.md`

## 7. 本轮优点

本轮把 E2E 从“必须依赖 Docker Desktop”降低为“优先 Docker，必要时本机 PostgreSQL fallback”。这更符合当前 Windows 开发机状态，也避免把 Docker Desktop / WSL2 问题误判为业务代码失败。

## 8. 本轮缺点与代价

Docker Desktop Engine 仍未修好。当前 E2E 是通过本机 PostgreSQL 17 跑通，不代表 Docker Desktop 已恢复。

后续如果希望完全走 Docker，需要用户处理 Docker Desktop Service、WSL2 或 Docker Desktop 登录/初始化问题，必要时重启电脑。

## 9. 验证与结果

已通过：

- `npm run db:generate`
- `npm run db:push`
- `npm run db:seed`
- `npm run typecheck`
- `npm run lint`
- `npm run build`
- `npm run test:e2e:v22`：2 passed
- `npm run test:e2e:v221`：3 passed
- `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\dev-check.ps1`：通过；脚本在 Docker Compose 失败后复用本机 PostgreSQL fallback，并完整跑通 Prisma、Seed、typecheck、lint、build 和两组 smoke。

Playwright 输出中出现 Next.js 的 cross origin dev warning，仅为 Next.js dev server 提醒，不影响本轮 smoke 结论。

## 10. 本轮结论

V2.2 / V2.2.1 smoke 失败根因已解除：数据库现在可连接，Prisma 和 Seed 已跑通，两组 smoke 已通过。

Docker Desktop 本身仍处于 Engine 无法启动状态，但当前项目本地测试可以通过 PostgreSQL fallback 稳定运行。

## 11. 下一轮建议

1. 如要恢复 Docker 路径，优先修复 Docker Desktop Service / WSL2，必要时以管理员身份启动服务或重启电脑。
2. 后续提交前可再跑一次 `scripts/dev-check.ps1`，确认 Docker 或 fallback 路径仍能完整跑通。
3. 不建议在 Docker Desktop 未修复前继续围绕 Docker 做业务判断；当前 E2E 以本机 PostgreSQL 路径为准。
