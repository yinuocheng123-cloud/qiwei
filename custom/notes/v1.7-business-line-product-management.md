# 版本记录：v1.7-business-line-product-management

## 1. 本轮目标

本轮目标是在现有《企业微信业务增长中台》上新增一个通用的“业务线／产品管理”模块。

这轮不是继续扩企业微信接口，也不是做电商商品、计费或公开 SaaS 注册，而是把原来分散在资料包、任务模板、标签建议和智能跟进助手里的“业务方向”收拢成租户级统一入口。

本轮目标类型属于：功能补充、结构收口、可维护性提升。

## 3. BusinessLine 模型说明

本轮新增 `BusinessLine` 模型，并配套：

1. `BusinessLineStatus`
   - `ACTIVE`
   - `PAUSED`
   - `ARCHIVED`
2. `BusinessLineCategory`
   - `SERVICE`
   - `PRODUCT`
   - `ACTIVITY`
   - `COURSE`
   - `SUPPLY_CHAIN`
   - `MEMBERSHIP`
   - `PARTNERSHIP`
   - `OTHER`

核心字段：

1. `tenantId`
   用于多租户隔离。
2. `name`
   业务线或产品名称。
3. `slug`
   租户内唯一标识。
4. `description`
   业务线说明。
5. `status`
   启用、暂停或归档状态。
6. `category`
   业务线分类。
7. `priority`
   排序优先级。
8. `targetCustomerTypes`
   Json，记录适合的客户类型。
9. `recommendedTagNames`
   Json，记录推荐标签与标签分组。
10. `recommendedMaterialIds`
    Json，记录绑定资料包 id。
11. `recommendedTaskTemplateIds`
    Json，记录绑定任务模板 id。
12. `defaultNextAction`
    业务线默认推荐下一步动作。
13. `notes`
    内部备注。

本轮继续采用 Json 轻量关联，而不是额外引入多张中间表，目的是先把系统能力跑通并保持最小改动。

## 4. 页面入口说明

新增页面：

- `/app/[tenantSlug]/business-lines`

导航名称：

- `业务线／产品`

页面能力：

1. 企业管理员与运营可新增业务线。
2. 企业管理员与运营可编辑业务线。
3. 企业管理员与运营可切换启用、暂停、归档。
4. 页面可查看：
   - 分类；
   - 状态；
   - 适合客户类型；
   - 推荐标签；
   - 关联资料包；
   - 关联任务模板；
   - 默认下一步动作；
   - 最后更新时间。
5. 销售可访问该页，但只能查看启用中的业务线，不可编辑。

## 5. 权限说明

本轮权限边界如下：

1. `TENANT_ADMIN`
   - 可新增、编辑、启用、暂停、归档本租户业务线。
2. `OPERATOR`
   - 可新增、编辑、启用、暂停、归档本租户业务线。
3. `SALES`
   - 可查看启用中的业务线列表；
   - 不可新增、编辑或改状态。
4. `PLATFORM_ADMIN`
   - 本轮不直接进入租户业务线管理。

所有业务线读写都基于 `tenantId` 过滤，不允许跨租户访问或修改。

## 6. 与资料包的关系

BusinessLine 可以绑定资料包 id。

落地效果：

1. 后台业务线页可直接看到每条业务线绑定了多少资料包。
2. 客户问题命中启用业务线时，智能跟进助手会优先把该业务线绑定的资料包放进建议回复结果中。
3. seed 中已为 `zhengmu-demo` 和 `zhengmu-platform` 分别补了对应业务线与资料包的绑定关系。

## 7. 与任务模板的关系

BusinessLine 可以绑定任务模板 id。

本轮没有进一步做“自动创建任务”，但已经把任务模板作为统一配置的一部分沉淀到业务线中：

1. 后台业务线页可查看业务线关联的任务模板数量与名称。
2. seed 中已把两个租户的典型任务模板挂到对应业务线上。
3. 后续如果要做“从业务线快速生成任务”或“业务线默认任务建议”，可以直接沿用这层数据。

## 8. 与智能跟进助手的关系

本轮增强了 V1.5 智能跟进助手：

1. 当客户问题命中启用业务线时，系统会优先读取该业务线的：
   - `recommendedMaterialIds`
   - `defaultNextAction`
2. 推荐资料会排到原有客户类型规则推荐之前。
3. 下一步动作会优先使用业务线的默认动作；若没有命中，再回退到原有客户类型／策略库逻辑。
4. 仍然不调用外部 AI，不接企业微信 API，不做自动回复。

## 9. 与智能标签建议的关系

本轮增强了 V1.5.1 智能标签建议：

1. 当客户问题命中启用业务线时，系统会优先读取该业务线的推荐标签。
2. 业务线标签会以高推荐强度并入原有规则标签结果。
3. 如果没有命中业务线，仍使用原有规则标签兜底。
4. 业务线为 `PAUSED` 或 `ARCHIVED` 时，不再进入推荐。
5. 仍然不会自动打标签，必须由销售、运营或企业管理员人工确认后才写入客户档案。

4. `npm run build`：通过。

本轮验证阶段额外确认了以下事实：

1. `BusinessLine` migration 已正确落到本地验证库，`public.BusinessLine` 表存在。
2. `zhengmu-demo` 的 4 条业务线和 `zhengmu-platform` 的 8 条业务线都能被 seed 与校验脚本识别。
3. 业务线页、客户详情页智能标签建议、跨租户访问控制都已通过浏览器端验证。

本轮 Playwright 收口过程中没有发现新的业务逻辑 bug，主要修正点集中在测试稳定性和本地环境顺序：

1. `run-v11-postgres-check.ps1` 在校验结束后会主动关闭临时 PostgreSQL，因此 Playwright 不能直接复用该脚本结束后的数据库状态；本轮改为单独保活 `55432` 数据库后再跑浏览器测试。
2. 业务线页里“会员服务”等文本同时出现在业务线、资料包和任务模板里，原始断言过宽，已收窄到业务线卡片或标题级定位。
3. 新建测试业务线在多次本地重跑时会命中租户内唯一键，因此测试已改为使用每次运行唯一的业务线名称与 slug，避免重复执行时误判。

## 12. 风险与未完成项

当前已知 trade-off 如下：

1. 业务线与资料包、任务模板的关联本轮仍使用 Json id 列表，优点是改动轻，缺点是数据库层约束不如中间表强。
2. 业务线命中逻辑目前仍是规则匹配，依赖名称、说明、标签文本和默认动作中的关键词，不是更复杂的语义理解。
3. 业务线管理页为了先保证可用性，采用单页表单和 checkbox 列表，没有做更细的弹窗、分页或搜索。
4. Playwright 目前对中文文案仍有一定依赖，后续如果业务线页标题或表单文案调整，记得同步收窄定位器，而不是放宽全文本匹配。

## 13. 下一步建议

1. 若 V1.7 验证稳定，下一轮可以考虑让客户详情页显式展示“当前命中的业务线”，方便销售理解建议来源。
2. 若业务线数量继续增加，后续可再考虑把资料包和任务模板关联升级为中间表。
3. 若运营侧有真实使用反馈，可继续补充业务线命中关键字和推荐标签词库，但仍不急着接外部大模型。
