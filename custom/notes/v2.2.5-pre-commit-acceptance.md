# 版本记录：v2.2.5-pre-commit-acceptance

## 1. 本轮目标

本轮目标是进入「提交前人工验收与边界整理」：不新增业务功能，不修改销售路径，不接真实企业微信，不接真实 AI，不 push，不 commit，只把 V2.1.9 到 V2.2.4 的连续改动整理成清晰的本地提交边界，并准备人工验收说明。

## 2. 背景与上下文

当前连续改动从 V2.1.9 开始，经过 V2.2、V2.2.1、V2.2.2、V2.2.3 和 V2.2.4，主线从“功能平台”逐步收口为“销售试点工作台”。

当前工作区仍有未提交改动，这是预期状态。本轮只做验收整理，不做提交动作。

## 3. 本轮连续改动范围

本轮连续改动主要包括五类：

1. 产品入口收口：首页、导航、Market Claw、业务配置从功能集合转向试点工作台。
2. 销售路径极简：销售只围绕工作台、客户、客户详情、AI 推荐回复和保存跟进工作。
3. AI 后台化：Market Claw、训练、沙盒、Provider、知识维护、训练审核等能力转入设置或后台治理，不进入销售主路径。
4. 本地环境标准化：补齐 Docker Compose、数据库脚本、PowerShell 检查脚本和本机 PostgreSQL fallback 文档。
5. 稳定性收口：dashboard、客户详情 AI 推荐区域、后台治理页增加局部查询失败兜底。

## 4. 产品主线变化

产品主线从“企业微信业务增长功能平台”收口为“熟客陪跑试点工作台”。当前阶段不追求自助 SaaS 化，也不继续扩展 AI 能力，而是优先让试点销售能在 10 分钟内完成一次客户跟进。

核心主线固定为：

客户进入 -> 今日待跟进 -> AI 推荐回复 -> 保存沟通记录 -> 跟进沉淀

## 5. 销售路径变化

销售路径被压缩为：

登录 -> 工作台 -> 客户列表 -> 客户详情 -> AI 推荐回复 -> 人工修改 -> 保存跟进 -> 下一步任务

销售不需要理解 AI Provider、Prompt、训练审核、候选知识、沙盒、企业微信配置、合规配置、审计日志或系统设置。

## 6. AI 后台化变化

AI 能力不再作为销售入口，而是作为客户详情页里的“AI 推荐回复”能力出现。销售看到的是回复建议、风险提醒、人工修改和保存跟进。

管理员和运营可通过设置页进入后台治理：

- AI 治理
- 知识维护
- 回复训练
- 训练审核
- AI 测试沙盒
- 回复记录
- 洞察复盘
- AI Provider

这些能力没有删除，只是从销售主路径中隐藏或转入后台。

## 7. 本地环境变化

本地环境从“手动判断 PostgreSQL 是否启动”整理为标准流程：

- `.env` 指向 `127.0.0.1:55432/wecom_growth_hub_demo`
- 新增 `docker-compose.yml` 用于 PostgreSQL 16
- 新增 `scripts/dev-check.ps1`
- 新增 `scripts/db-reset-local.ps1`
- 新增本地环境说明 `custom/dev/local-env-setup.md`
- 支持 Docker Desktop 不可用时使用本机 PostgreSQL 17 fallback

当前 Docker Desktop / Docker Engine 仍不可用，但本机 PostgreSQL fallback 已经跑通。

## 8. 稳定性收口变化

V2.2.4 已对页面数据读取做局部兜底：

- dashboard 单个统计失败时回退为 0 或空列表。
- dashboard 显示“当前统计暂不可用，不影响客户跟进。”
- 客户详情页 AI 推荐辅助数据失败时，不影响客户详情主页面。
- AI 推荐区域显示“当前 AI 推荐暂不可用，可先手工记录跟进。”
- 后台治理页复盘、训练、回复记录读取失败时显示业务化提示。

本轮不暴露 Prisma、Provider、Prompt、向量等技术词。

## 10. 未解决风险

Docker Desktop / WSL2 仍未完全恢复：

- Docker CLI 和 Compose 可识别。
- Docker Engine 仍可能返回 `Docker Desktop is unable to start`。
- WSL 状态曾出现异常输出。
- 当前测试依赖本机 PostgreSQL fallback 稳定运行。

该风险属于本地开发环境问题，不是业务代码问题。

另一个风险是当前连续改动跨度较大，提交前应人工确认首页、销售路径、设置页和后台治理入口是否符合预期。
