# 版本记录：v1.8.1-permission-matrix-page

## 1. 本轮目标

本轮目标是在 V1.8 和 V1.7.1 已经完成的角色化导航与权限收口基础上，新增一个“权限矩阵说明页”，把当前系统里的角色、权限、管理边界和使用边界页面化、文档化、可解释化。

本轮优先级高的原因有三点：

1. 当前系统已经具备多租户、真实登录、RBAC、客户管理、业务线、客户导入、智能跟进助手、智能标签建议、审计日志和 CNAS 项目接入能力，但角色边界更多体现在代码与导航里，缺少一个给企业管理员解释清楚的统一入口。
2. 整木网开始自用后，老板、运营、销售都会问“为什么我看不到某个菜单”“为什么业务线不能删除”“为什么企微配置不给销售看”，这些问题适合沉淀成后台说明页，而不是每次口头解释。
3. 用户明确要求本轮只做“权限矩阵说明页”和文档收口，不新增复杂角色体系、不接企业微信 API、不改核心业务逻辑。

本轮目标属于：可维护性提升、使用边界澄清、角色化说明补全。

## 3. 页面入口说明

本轮新增页面入口：

- `/app/[tenantSlug]/permissions`

导航名称：

- `权限说明`

页面名称：

- `权限矩阵`

页面用途：

1. 解释不同角色看到不同菜单的原因；
2. 解释哪些模块是“使用系统”，哪些模块是“管理系统”；
3. 解释业务线、企微配置、审计日志、客户导出等关键边界；
4. 作为整木网自用培训页和后续对客户交付时的辅助说明页。

## 4. 访问权限说明

本轮权限策略如下：

1. `TENANT_ADMIN` 可访问权限矩阵说明页；
2. `OPERATOR` 可只读访问权限矩阵说明页；
3. `SALES` 不显示导航入口，直接访问会跳转 `/forbidden`；
4. `PLATFORM_ADMIN` 不因为本页扩大租户业务权限；
5. 跨租户访问继续沿用 `requireTenantAccess` 的既有校验逻辑。

实现上继续复用现有权限边界，没有新增新的数据库角色，也没有新增新的权限模型字段。

## 5. 角色说明

页面中按当前系统角色补齐了角色说明卡片：

1. `PLATFORM_ADMIN`
   - 系统控制方，负责租户、系统配置、安全、平台级审计和运维
   - 强调平台掌握系统，但企业拥有客户业务数据

2. `TENANT_ADMIN`
   - 企业老板、总经理、业务负责人
   - 负责看全局、定方向、管结果
   - 说明其可管理业务，但不能破坏历史

3. `OPERATOR`
   - 企业运营
   - 负责业务资产、内容承接、活动承接和策略维护
   - 明确不建议开放导出、完整审计和企微敏感配置

4. `SALES`
   - 销售／顾问
   - 负责日常客户跟进、任务推进、建议回复和标签确认
   - 明确“销售只能使用系统，不应该管理系统”

5. `VIEWER`
   - 当前仅作为未来扩展角色说明展示
   - 不落库、不开放真实配置能力

## 6. 权限矩阵说明

页面中新增了一张完整的权限矩阵表，覆盖以下模块：

1. 租户管理
2. 平台审计
3. Dashboard
4. 客户列表
5. 客户详情
6. 客户导入
7. 客户导出
8. 业务线／产品
9. 资料包
10. 策略库
11. 任务模板
12. 销售工作台
13. 跟进记录
14. 智能跟进助手
15. 智能标签建议
16. 审计日志
17. 企业微信配置
18. 演示说明

矩阵没有重新定义系统权限，而是把当前已经存在的角色边界做成可视化说明，便于解释：

1. 为什么 `PLATFORM_ADMIN` 不参与租户日常销售跟进；
2. 为什么 `TENANT_ADMIN` 拥有最完整的租户业务管理入口；
3. 为什么 `OPERATOR` 可以维护业务资产但默认不开放导出、审计和企微敏感配置；
4. 为什么 `SALES` 只保留“我的客户”“销售工作台”“客户详情”“智能建议”等轻量日常入口；
5. 为什么 `VIEWER` 当前只作为规划说明而不真正实现。

## 7. 关键权限边界说明

页面中单独增加了“关键边界”模块，包含以下说明：

1. 业务线不做物理删除
   - 只做启用、暂停、归档
   - 避免关联客户、标签、资料包、任务模板、跟进记录和审计历史断层

2. 企业微信配置必须高权限
   - secret、token、EncodingAESKey、回调地址和应用配置不对销售和普通运营开放
   - 原则是可配置但不明文展示，可看状态但不泄露密钥

3. 审计日志不是普通数据
   - 审计日志是管理和风控工具，不是销售工具
   - 企业管理员看租户审计，平台管理员看平台审计

4. 客户导出要严格控制
   - 建议只有企业管理员能导出
   - 导出必须写入审计日志
   - 导出内容仅限客户基础数据

5. 销售只能使用系统，不管理系统
   - 销售界面要轻
   - 只保留任务、客户、跟进建议和标签建议，不暴露全局配置型入口

## 10. 风险与未完成项

1. 当前权限说明页是静态说明页，不是可配置权限中心；
2. 矩阵内容依赖当前代码中的角色边界，后续如果权限策略继续扩展，需要同步维护该说明页；
3. `VIEWER` 仍然只是规划说明，不是实际落地角色；
4. 页面没有接入“当前用户实际权限自动比对”，因此它的职责是解释，而不是动态审计。

## 11. 下一步建议

1. 如果后续继续扩后台，可以把当前散落的角色判断进一步沉淀成统一的能力矩阵常量，减少“说明页内容”和“代码权限”双处维护成本。
2. 如果整木网开始频繁给外部客户演示，可考虑把权限矩阵页与 `demo-guide` 做更明显的互链，分别承担“系统怎么用”和“为什么这样分权”两种说明职责。
3. 如果未来真的实现 `VIEWER`，优先做脱敏只读和范围受限的观察视角，不要直接复制企业管理员菜单。
