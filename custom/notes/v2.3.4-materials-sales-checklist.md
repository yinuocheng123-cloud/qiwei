# 版本记录：v2.3.4-materials-sales-checklist

## 1. 本轮目标
本轮目标是把资料管理从后台编辑器风格调整为销售资料清单风格，让销售一眼知道“今天有哪些资料可以发给客户”。

## 2. 背景与上下文
V2.2.7 已经把资料页往清单化方向收口，但页面仍然保留了偏后台 CMS 的编辑感。销售看到的是较重的编辑区，而不是“可发送清单”。

## 3. 问题分析
主要问题不是资料功能本身，而是展示方式：
1. 默认展示编辑表单太重。
2. 资料类型看起来像附件系统，不够像销售发送链接清单。
3. SALES 进入页面时，第一眼看到的是后台管理感，而不是可发资料。

## 4. 候选方案比较
### 方案 A：只改文案
优点：改动小。
缺点：结构不变，CMS 感还在。

### 方案 B：新增上传系统 / 文件系统
优点：功能完整。
缺点：超出本轮边界，也违背“不做文件系统”的要求。

### 方案 C：保持现有数据结构，改成折叠清单 + 链接模式
优点：最小改动，能直接把页面压成销售清单。
缺点：只是展示层和交互层收口，没有引入更强的资料治理能力。

## 5. 最终决策
本轮采用“折叠清单 + 链接模式 + 轻量状态”的方案：
- 默认只显示标题、类型、状态和展开入口。
- 展开后才显示链接、描述、创建时间和编辑表单。
- 新增资料也采用折叠面板，避免首页直接出现大表单。
- 类型收口为链接、PDF、文档、视频。

## 6. 具体实现
修改文件：
1. `src/app/app/[tenantSlug]/materials/page.tsx`
2. `src/components/MaterialChecklist.tsx`
3. `tests/v227-materials-checklist-smoke-e2e.spec.ts`
4. `AGENTS.md`

核心改动：
1. 页面只按客户类型分组展示实际资料，不再默认展示策略模板式的重清单。
2. 用 `details / summary` 做轻量展开，默认不露出大 textarea。
3. 新增资料入口改成折叠面板，文案明确说明资料链接模式。
4. 状态前端计算：有标题 + 有链接即“已完善”，缺链接即“待补充”。
5. 资料类型只保留链接、PDF、文档、视频，旧的 image 值在展示层归入文档。

## 7. 本轮优点
1. SALES 视角更像“今天有哪些资料可以发给客户”。
2. 默认不再看到大表单，后台感明显下降。
3. 不需要改数据库，不需要接上传服务。
4. 仍然复用原有资料创建和更新 action，风险较低。

## 8. 本轮缺点与代价
1. 资料状态仍然是轻量规则，不能判断链接是否真的可访问。
2. 没有做文件上传和文件管理。
3. 旧的 `image` 类型没有迁移，只是在展示层做了收口。

## 9. 验证与结果
计划验证：
- `npm.cmd run typecheck`
- `npm.cmd run lint`
- `npm.cmd run build`

同时会人工检查 SALES 视角是否更轻、页面是否更像销售清单而不是 CMS。

## 10. 本轮结论
资料页更适合被看作“销售发送清单”，而不是后台内容管理页。
在不改数据库和上传链路的前提下，折叠清单 + 链接模式是当前最稳的收口方式。

## 11. 下一轮建议
1. 如果后续要继续优化，可以再细化“待补充”提示和资料分类。
2. 如果需要更强治理，再考虑资料模板或质量检测，但那是下一阶段，不在本轮。
3. 先让销售用起来，再看哪些资料最常被发，之后再决定是否补充更多治理能力。
