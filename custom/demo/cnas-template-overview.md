# CNAS 模板说明：平台底座上的试点样板

## 1. 定位

CNAS 不是一套独立系统，也不是新的 Agent。V2.5 中，CNAS 被重新定位为 MarketClaw 平台底座上的一个试点模板，用来验证“同一套客户跟进与销售协作能力，能否承接专业服务行业语境”。

## 2. Platform 提供什么

- 多租户、登录、角色权限和租户隔离。
- 客户、线索、标签、跟进记录、任务和资料清单。
- 业务线、客户类型策略、任务模板和销售资料组织方式。
- MarketClaw 推荐回复、训练样本、知识维护、风险提示和内部治理边界。
- 企业微信和 AI 的配置预留与内部提醒占位。

## 3. Template 提供什么

- `Tenant.templateKey = cnas-pilot`。
- `Tenant.templateName = CNAS 认可试点模板`。
- CNAS 认可指南业务线、资料包、任务模板、问卷入口和 A/B/C 初步判断规则。
- 面向 CNAS 认可咨询的客户话术、标签和来源归因示例。

## 4. 明确不做什么

- 不新增复杂模板系统或模板管理后台。
- 不新增模板表、模板运行时或模板继承机制。
- 不接真实企业微信 API。
- 不接真实 AI。
- 不做 Agent。
- 不改销售主路径。
- 不扩大 SALES 权限。

## 5. 当前试点路径

1. 公开入口：`/forms/cnas-path-check`。
2. 目标租户：`zhengmu-platform`。
3. 租户标注：`templateKey = cnas-pilot`，`templateName = CNAS 认可试点模板`。
4. 后台承接：继续复用客户详情、资料清单、任务、跟进记录和 MarketClaw 推荐回复。

## 6. 后续建议

如果后续需要支持更多行业模板，优先继续使用 `templateKey/templateName` 标注和 seed 数据差异，不要提前引入模板引擎。只有当多个试点都出现稳定的模板生命周期需求时，再评估是否新增独立模板模型。
